# Результаты пилота MBPP

## Методика

Пилот проведён на первых 20 задачах зафиксированной случайной выборки `MBPP sanitized/test` с seed 42. Для каждой задачи подготовлены два основных мутанта и один hardcode-контроль.

`task_id`: 113, 61, 406, 129, 119, 479, 88, 405, 77, 388, 477, 447, 273, 71, 286, 237, 56, 20, 72, 109.

Основная группа содержит 13 сдвигов границы, 14 замен операторов и 13 пропусков краевого случая. Неверность каждого мутанта подтверждена отдельным контрпримером: эталон проходит этот `assert`, мутант — нет. Hardcode возвращает ответы только для штатных входов и `None` для неизвестного входа.

Все проверки выполнялись в отдельных процессах `bwrap` без сети и доступа к проекту, с лимитами времени, памяти и вывода.

## Интерпретация

Пилот проверяет жизнеспособность формата мутантов, контрпримеров и раннера. Он не используется для окончательного вывода по порогу 5%: 40 основных мутантов меньше минимального объёма 150, установленного в README.

На пилотном срезе особенно часто пропускались ошибки обработки краевых случаев, но размеры групп малы, а мутанты сконструированы вручную. Поэтому различия между типами следует считать наблюдением для настройки основного эксперимента, а не итоговым выводом.

Отдельно учтено ограничение task 129: его эталон повторно считает главную диагональ. Контрпримеры для этой задачи выбраны среди известных корректных magic square и не используют дефект эталона.
