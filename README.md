## Карточка проекта

### Исследовательский вопрос

Штатные тесты MBPP на `sanitized/test` ошибаются относительно заведомо неверных решений: на каких типах мутаций и при каких свойствах задачи (тип ответа, покрытие краевых случаев) неверный код проходит все assert-ы

### Данные и срез

- **Датасет:** MBPP, [`google-research-datasets/mbpp`](https://huggingface.co/datasets/google-research-datasets/mbpp) на Hugging Face.
- **Конфигурация и срез:** конфиг `sanitized`, сплит `test` — 257 задач на Python, у каждой эталонное решение и обычно 3 `assert`-теста. Берём все задачи сплита, мутанты пишем для 150 задач, отобранных случайно с seed 42.
- **Лицензия:** CC-BY-4.0.
- **Загрузка:** `load_dataset("google-research-datasets/mbpp", "sanitized")`.

### Эталон и метод

- **Эталон (прокси):** неверность по построению — мутанты эталонного кода: сдвиг границы, замена оператора, пропуск крайнего случая, хардкод ответов из тестов. Для каждого мутанта пишем свой тест-контрпример, на котором он падает, а эталон проходит.
- **Что эталон не покрывает:** ошибки, которых мы сами не придумали, и качество кода сверх корректности.
- **Оцениваемый оценщик:** прогон штатного `test_list` — решение считается верным, если прошли все `assert`-ы задачи.
- **Базовое сравнение:** эталонные решения на тех же тестах (проверено: проходят 427 из 427 задач `sanitized`) и заглушка `return None` (0 из 427). То есть оценщик не отвергает верный код и ловит грубо неверный.

### Метрика и критерий

- **Метрика ошибки:** доля ложных пропусков = число мутантов, прошедших все штатные тесты / число всех мутантов; с 95% интервалом Уилсона, отдельно по типам мутаций.
- **Контроль ложных отказов:** эталоны, упавшие на тестах / все эталоны.
- **Численный критерий:** говорим «штатные тесты пропускают неверный код», если нижняя граница 95% интервала Уилсона для доли ложных пропусков выше 5% при ≥150 мутантах. Ниже 5% тесты на этом срезе ведут себя почти как оракул.
### Риск и границы

- **Возможная ошибка оценщика:** высокий балл без решения задачи — код, который подставляет ответы на три тестовых входа, или решение, верное только на «удобных» входах из тестов. Обратная ошибка — отказ верному коду из-за формата: `list` вместо `tuple`, другой порядок элементов, `float` без допуска.
- **За границами проекта:** не обучаем и не дообучаем модели, не генерируем решения языковыми моделями, не сравниваем методы между собой, не берём второй датасет (MBPP+, HumanEval) и другие языки программирования.

### Следующий шаг

- Пилот на 20 задачах из среза: написать по 2–3 мутанта на задачу, прогнать штатные тесты и для каждого мутанта убедиться тестом-контрпримером, что он действительно неверен.
